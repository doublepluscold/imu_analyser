# План: витягти дані і пінаут напряму зі STM32 по SWD

Читаємо дані IMU наживо з RAM і пінаут з регістрів працюючої прошивки. Все **тільки на читання**.

## Що дає і чого не робимо

- **Дані IMU** - live-read з RAM. Неруйнівно, працює навіть на RDP1.
- **Пінаут** - dump регістрів GPIO/RCC. Неруйнівно, працює на RDP1.
- **Бінарник прошивки** - тільки на RDP0.
- **Заборонено:** писати флеш, міняти Option Bytes, знижувати RDP. Поки все read-only, ризик нульовий, запасна плата навіть не потрібна як страховка.

## Головний гейт (прочитати перед стартом)

Весь цей шлях тримається на двох умовах, які з'ясуються на першому підключенні:
1. **RDP не 2.** RDP2 = SWD мертвий назавжди → шлях відпадає, йди на логічний аналізатор (розділ 6).
2. **Прошивка не вимкнула SWD.** Перевірка: attach під працюючою прошивкою проходить. Якщо attach не йде, а "under reset" йде - значить прошивка забрала PA13/PA14 → live-read неможливий (під ресетом периферія ще не налаштована, RAM порожня) → теж розділ 6.

## Крок 0: залізо

- **SWDIO** дротом напряму на пін 72 (PA13): на роз'ємі P1 його немає.
- **Твоє підключення - 4 дроти:** SWDIO, SWCLK, GND, NRST. Без VTref.
- ST-Link ↔ модуль:

| ST-Link | Куди | Обов'язковість |
|---|---|---|
| SWDIO | дріт на пін 72 | так |
| SWCLK | P1.4 | так |
| GND | P1.3 | так |
| NRST | P1.1 | так (для режиму "under reset") |
| VTref | P1.5 | **ні** - клон бере опору зі своїх 3.3 В; з'єднання з живою платою дасть конфлікт джерел |

- Модуль живиться від своїх 24 В окремо. GND ST-Link спільна з GND модуля.

## Крок 1: інструменти

- **STM32CubeProgrammer** - для RDP і (якщо RDP0) дампу флешу.
- **pyOCD** + скрипт `swd_probe.py` - для live-read і пінауту:
  ```
  pip install pyocd
  # якщо ціль невідома: pyocd pack install stm32h743vitx
  ```
- Альтернатива: OpenOCD (`interface/stlink.cfg` + `target/stm32h7x.cfg`), читання через `mdw` у циклі. Для читання без halt зручніший pyOCD (режим attach).

## Крок 2: підключення + рівень RDP

1. У CubeProgrammer: спершу "hot plug" (під працюючою прошивкою). Це також перевіряє головний гейт - чи живий SWD при роботі прошивки (потрібно для live-read). Не пройшло - став "under reset" (NRST уже припаяний). Частота SWD 100-500 кГц.
2. Прочитати Option Bytes, занотувати RDP. Або скриптом:
   ```
   python3 swd_probe.py rdp
   ```
3. Гілки:
   - **RDP0** - можна все, включно з дампом флешу (Крок 3).
   - **RDP1** - флеш недоступний, але пінаут (Крок 4) і дані (Крок 5) читаються. **RDP не знижувати** - це mass-erase.
   - **RDP2** - стоп, розділ 6.
4. Якщо attach під прошивкою не проходить взагалі → SWD вимкнено прошивкою → розділ 6.

---

## Крок 3 (тільки RDP0): дамп прошивки

```
STM32_Programmer_CLI -c port=SWD mode=UR -r 0x08000000 0x200000 fw.bin
```
Зберегти. Реверс у Ghidra - опційно, пізніше. Для власної прошивки ініт SCH1633 бери з драйвера PX4 `SCH16T`.

## Крок 4: пінаут через dump регістрів (неруйнівно)

Прошивка вже налаштувала всі піни - зчитуємо результат:
```
python3 swd_probe.py pins
```
Скрипт вивалює всі піни в режимі AF або output із номером AF і підказкою сімейства. Що шукати:
- **Блок пінів AF5** - SPI до трьох SCH1633 (SCK/MISO/MOSI). Поряд **OUT-піни** - це chip-select (по одному на чіп).
- **AF7/AF8 піни** - USART: один на ADM3232E (зовнішній RS-232), інший на GPS.
- Точний сигнал кожного AF-піна звірити з таблицею alternate-function у datasheet H743 (номер AF + пін → функція).

Так отримуєш карту: який SPI і які CS на IMU, який USART зовнішній. Це і є пінаут для власної прошивки.

## Крок 5: дані IMU через live-read RAM (неруйнівно)

Прошивка тримає поточні значення IMU десь у RAM. Знаходимо їх кореляцією з рухом.

1. **Локатор** (порівнює дисперсію "спокій" vs "рух"):
   ```
   python3 swd_probe.py locate --addr 0x20000000 --size 0x4000
   ```
   Тримаєш плату нерухомо (Enter), потім крутиш/трясеш (Enter). Скрипт покаже адреси, що міняються синхронно з рухом - це гіро й акселерометр. Якщо в DTCM (0x20000000) пусто, спробуй AXI SRAM:
   ```
   python3 swd_probe.py locate --addr 0x24000000 --size 0x8000
   ```
   Регіони H743: DTCM 0x20000000, AXI SRAM 0x24000000, SRAM1-3 0x30000000, SRAM4 0x38000000.

2. **Спостереження** знайдених адрес наживо:
   ```
   python3 swd_probe.py watch 0x20001234 0x20001238 0x2000123C
   ```
   Показує int32 і float32. Орієнтир: у спокої акселерометр дає вектор ~9.81 (одна вісь близько 9.81, решта біля 0), гіро біля 0 і стрибає при обертанні. Знайшов трійку осей акселя і трійку гіро - дані витягнуто.

Читання фонове, ядро не спиняємо (halt заморозив би значення). Все неруйнівно.

---

## Крок 6: якщо SWD мертвий (RDP2 або вимкнено прошивкою)

SWD-шлях відпав. Запасний план без MCU взагалі:
- Логічний аналізатор на SPI між платами (SCK/MISO/MOSI + 3 CS) під працюючою прошивкою.
- Декод SPI + datasheet SCH16xx / драйвер PX4 `SCH16T` = ті самі сирі дані, нуль ризику.
- Заодно мапиш пінаут конектора (які лінії SPI на яких пінах).

---

## Read-only чеклист

- [ ] Не писати флеш, не міняти Option Bytes, не знижувати RDP.
- [ ] Якщо CubeProgrammer пропонує розблокувати / прибрати захист - відмовитися.
- [ ] Ядро не спиняти під час пошуку/читання даних (тільки фонове читання).
- [ ] SWDIO лишень на пін 72; VTref на клоні не підключати.
- [ ] Спільна GND модуля і ST-Link.
